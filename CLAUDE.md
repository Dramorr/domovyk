# CLAUDE.md — Домовик

Домовик — система прямої оренди житла у Львові між власником і орендарем, без ріелторів. Покриває весь цикл: пошук → заявка → показ → договір (підпис через Дію) → життя в оренді (оплати, комуналка, чат, ремонти) → завершення й відгуки.

Зараз: **бета, Telegram Mini App + бот** ([ADR 0001](docs/decisions/0001-telegram-mini-app-first.md)). Екрани — у Mini App (`web/`, хостинг GitHub Pages), бот — вхід, сповіщення й чат. Далі той самий бекенд обслуговуватиме сайт і мобільний застосунок.

Репозиторій **публічний** (код відкритий для перегляду, ліцензії немає — усі права захищені). Тому:
- жодних секретів, токенів, реальних персональних даних, документів чи квитанцій у git — навіть у тестах і фікстурах (лише вигадані дані);
- списки «ріелторських» слів, пороги ризику й скарг — у БД/конфігурації, не в коді;
- у фронтенді (`web/`) секретів не буває: усе, що там є, бачать усі. Права перевіряє лише бекенд.

- Повне ТЗ: `docs/SPEC.md` (вимоги мають ID `FR-...` — посилайся на них у комітах).
- Цільова схема БД: `db/schema.sql`.
- Сценарії інтерфейсу (екрани, кнопки, стани, сповіщення; де живе екран — Mini App чи бот): `docs/BOT_FLOWS.md`. Екрани й хендлери будуй за ним; змінився сценарій — онови документ.
- Бренд-файли (логотип, маскот): `assets/brand/`.
- Рішення: `docs/decisions/NNNN-назва.md` (короткі ADR).

## Мова

- Відповідай власнику проєкту (Олег) **українською**, на «ти». **Ніколи не використовуй російську** — ні в коді, ні в текстах, ні в коментарях.
- Тексти для користувачів — лише українською, тільки у файлах локалізації (`src/domovyk/interfaces/telegram/texts/uk.py` для бота, `web/src/locales/uk.json` для Mini App), не в хендлерах і не в компонентах.
- Ідентифікатори коду, назви таблиць і полів — англійською. Коментарі й docstring — українською або англійською, але однаково в межах файлу.

## Незмінні правила (не порушувати без явного рішення Олега)

1. **Домовик не проводить гроші.** Жодного еквайрингу для оренди, депозитів чи комуналки. `payments` — лише облік фактів оплати (квитанції, підтвердження готівки). Причина: прийом платежів на користь інших — ліцензована платіжна послуга (НБУ).
2. **Бот і API — тонкі.** Хендлери в `interfaces/` викликають лише сервіси модулів. Ніякого SQL, ORM чи сесій у хендлерах.
3. **Модулі не лізуть один в одного.** Інший модуль використовується лише через його `service.py` (публічні функції/класи). Імпортувати чужі `repository.py` чи `models.py` заборонено.
4. **Усе зовнішнє — за `Protocol`** у `src/domovyk/adapters/<щось>/base.py`, реалізації поруч. Вибір реалізації — в `config.py` / контейнері залежностей. Бізнес-логіка не знає, чи файли лежать у папці чи в S3, чи підпис прийшов з порталу Дії чи з API.
5. **Верифікація власності обов'язкова** перед публікацією оголошення й створенням оренди. Обхід — лише `DEV_SKIP_OWNERSHIP_CHECK=true` при `APP_ENV=dev`. Якщо прапорець увімкнено в іншому середовищі, застосунок має впасти на старті (тест на це обов'язковий).
6. **Строк оренди обов'язковий і ≤ 35 місяців** (інакше потрібен нотаріус). Перевіряється і в домені, і в БД.
7. **Персональні дані — мінімум.** РНОКПП і телефони для банів — лише HMAC-SHA256 (`core/crypto.py`). Реквізити оплати — шифрування Fernet. У логах маскуємо телефони, картки, ПІБ.
8. **Не скрейпимо** кабінети комунальників і сторонні сайти.
9. **Контакти й точна адреса** відкриваються лише після схвалення заявки.

## Стек

- Python 3.12, `uv` для залежностей.
- aiogram 3 (бот), FastAPI (API для Mini App/сайту; автентифікація через перевірку `initData`), Pydantic v2, pydantic-settings.
- Mini App: React + TypeScript + Vite, `pnpm`; типи API генеруються з OpenAPI-схеми FastAPI.
- SQLAlchemy 2 (async) + asyncpg, Alembic, PostgreSQL 16 + PostGIS.
- Redis: FSM бота + черга задач arq (воркер).
- WeasyPrint + Jinja2 (PDF договорів), pdfplumber (квитанції), asn1crypto (розбір підписів), imagehash (pHash фото).
- pytest, pytest-asyncio, testcontainers; ruff; mypy (strict для `domain/` і `modules/`).

## Структура

```
src/domovyk/
  config.py              # Settings (pydantic-settings), APP_ENV, прапорці
  core/                  # спільне: crypto (HMAC/Fernet), clock, ids, помилки, логування
  domain/                # чиста логіка без I/O: enum-и, правила, машини станів
  modules/
    users/  properties/  listings/  search/  applications/  showings/
    leases/  contracts/  payments/  utilities/  chat/  maintenance/
    reviews/  moderation/  notifications/  analytics/
      ├── service.py     # ПУБЛІЧНИЙ інтерфейс модуля
      ├── repository.py  # доступ до БД (лише всередині модуля)
      ├── models.py      # ORM-моделі
      └── schemas.py     # Pydantic DTO, які повертає сервіс
  adapters/
    storage/   geocoder/   signing/   receipts/   pdf/   notifier/
      ├── base.py        # Protocol
      └── <реалізація>.py   (local.py, s3.py, diia_portal.py, monobank.py, ...)
  interfaces/
    telegram/            # роутери aiogram, клавіатури, FSM-стани, texts/uk.py
    api/                 # FastAPI роутери (для Mini App)
  workers/               # arq-задачі: нарахування, нагадування, автопідтвердження, outbox
web/                     # Telegram Mini App (React + TS + Vite), деплой на Pages у /app/
  src/locales/uk.json    # тексти Mini App
site/                    # лендинг на GitHub Pages (корінь сайту)
migrations/              # Alembic
tests/unit/  tests/integration/
db/schema.sql            # цільова модель
docs/
```

## Команди

```bash
docker compose up -d db redis          # Postgres+PostGIS і Redis
uv sync                                # залежності
uv run alembic upgrade head            # міграції
uv run python -m domovyk.interfaces.telegram   # бот (long polling у dev)
uv run python -m domovyk.interfaces.api        # API для Mini App (http://127.0.0.1:8000, /docs у dev)
uv run python -m domovyk.dev                   # dev одним процесом: API + тунель ngrok + бот (docs/TUNNEL.md)
uv run arq domovyk.workers.WorkerSettings      # воркер
uv run pytest                          # тести
uv run ruff check . && uv run ruff format --check . && uv run mypy src
pnpm -C web install && pnpm -C web dev         # Mini App локально (для Telegram — через HTTPS-тунель)
pnpm -C web build && pnpm -C web lint          # збірка й лінт Mini App
uv run python -m domovyk.interfaces.api.export_openapi > web/openapi.json && pnpm -C web gen:api   # змінив API — онови типи
```

Інтеграційні тести (`tests/integration/`, testcontainers) потребують Docker; без нього вони пропускаються локально, але завжди йдуть у CI.

Якщо команди ще не існують (на початку M0) — створи їх саме такими, щоб цей файл лишався правдою.

## Конвенції

- Усе асинхронне. Транзакція = одна бізнес-операція сервісу (unit of work), не хендлер.
- Сервіси приймають і повертають DTO з `schemas.py`, а не ORM-об'єкти.
- Доменні помилки (`core/errors.py`) — не HTTP і не Telegram. Інтерфейси перекладають їх у повідомлення користувачу.
- Машини станів (`domain/`) — явні таблиці дозволених переходів. Перехід лише через функцію домену.
- Сповіщення лише через outbox: сервіс пише в `notifications` з `dedupe_key`, воркер відправляє через `adapters/notifier`.
- Події аналітики (`events`) — через `modules/analytics/service.py`. Перелік подій у SPEC, FR-BETA-2.
- Час: у БД `timestamptz` (UTC). Для користувача — `Europe/Kyiv`. «Зараз» беремо з `core/clock.py`, щоб тести могли його підмінити.
- Гроші: ціни й орендна плата — `int` гривні; фактичні оплати — `Decimal`.
- Нові ставки, строки й пороги (вікно оскарження, поріг скарг, податкові ставки, вікна показників) — у конфігурації або БД, не захардкоджені в логіці.

## Робочий процес

- Працюємо етапами M0 → M8 зі SPEC (розділ 10). Не перестрибуй етапи без запиту.
- Перед великою зміною — короткий план, і лише потім код.
- Зміна схеми: міграція Alembic **і** оновлення `db/schema.sql` в одному коміті.
- Кожна нова функція — з тестами: юніт для сервісу (фейкові репозиторії), інтеграційний для запитів і обмежень БД.
- Важливе рішення (бібліотека, зміна правила, відхід від SPEC) — ADR у `docs/decisions/`.
- Змінились вимоги — онови `docs/SPEC.md` у тому ж коміті.
- Секрети лише в `.env` (не в git). Шаблон — `.env.example`.

## Відомі нюанси предметної області

- «Орендар» і «власник» — не типи акаунта, а ролі в оренді. `users.role` — лише `user` / `moderator` / `admin`.
- Оренда: рівно один `responsible` орендар (обов'язковий) + будь-яка кількість `co_tenant` (усе для них необов'язкове).
- Оренда стає `active` лише після підписів власника й відповідального орендаря (або «договір поза Домовиком» для пар за запрошенням).
- Підписання (бета): PDF → кожна сторона підписує на порталі Дії → завантажує файл підпису в бот → `adapters/signing/diia_portal.py` розбирає сертифікат, звіряє документ і ПІБ.
- Оплата за квитанцією: збіглося все → `auto_accepted` + вікно оскарження власником → `confirmed`. Розбіжність або готівка → `pending_landlord`.
- Вікна подачі показників — у `utility_providers.window_rule` (Львів, листопад 2026; перевіряти).
- Скарги рахуються від **різних** людей; 3+ → справа модератору й статус `under_review`.

## Бренд і голос

- Назва: **Домовик** (латиницею Domovyk). Пакет Python — `domovyk`.
- Логотип — голова маскота (`logo-mark.svg`): зелений ковпак із загнутим кінчиком і бурштиновим помпоном, темно-зелена смуга, біла борода, рум'янець і ніс. Іконка застосунку (`app-icon.svg`) і аватар бота (`bot-avatar.svg` → `bot-avatar.png`, 640×640) — та сама голова на кремовому колі (#F6F1E7) на зеленому тлі. Знак-ключ більше не використовуємо.
- Маскот — гном-домовик (варіант C): високий ковпак з помпоном, очі сховані під ковпаком, біла борода. Базова поза — махає рукою (ключа немає ніде); ліхтарик — окрема поза (турбота, світло, блекаути). Персонаж оригінальний.
- Кольори: зелений #1E4D3B (основний), темно-зелений #163A2C, бурштиновий #F2A93B (акцент). Шрифти: Unbounded (заголовки, логотип), Manrope (текст).
- Голос (бот і Mini App): від імені Домовика, тепло, коротко, по-людськи, на «ти» або нейтрально. Без канцеляриту і без жартів у критичних повідомленнях (прострочення, скарги, бани, юридичні моменти — там спокійно і чітко).
- Приклад: «Нагадую: завтра день оплати оренди. Реквізити вже тут, натисни «Оплатити».»
