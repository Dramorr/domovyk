# 0001 — Mini App як основний інтерфейс з беті, бот — вхід і сповіщення

- Статус: **прийнято**
- Дата: 2026-11-04
- Автор: Олег
- Зачіпає: SPEC §1, §5.13, §7, §8, §9.1, §10; `BOT_FLOWS.md`; `CLAUDE.md`

## Контекст

SPEC v0.2 будує бету як чат-бот: усі екрани — повідомлення з inline-кнопками і стани FSM, а Telegram Mini App — наступний канал «пізніше».

Більшість сценаріїв Домовика погано лягають у чат: фільтри пошуку з десятком параметрів, галерея фото, карта, календар показів, картка оренди з вкладками, історія оплат і показників. У боті це десятки станів FSM і екранів, які потім однаково довелося б переробити під Mini App. Бекенд за SPEC і так «тонкі входи + сервіси модулів», тож API потрібен у будь-якому разі.

Репозиторій публічний, GitHub Pages уже налаштовано — це безкоштовний HTTPS-хостинг статики, якого достатньо для фронтенду Mini App.

## Рішення

1. **Основний інтерфейс беті — Telegram Mini App.** Усі екрани з `BOT_FLOWS.md` (пошук, оголошення, об'єкти, верифікація, оренда, договір, оплати, лічильники, профіль, налаштування сповіщень, модерація) реалізуються в Mini App.
2. **Бот лишається, але вузьким:**
   - вхід: `/start`, кнопка меню бота (`Відкрити Домовика`), deep links → відкривають Mini App на потрібному екрані (`startapp=<параметр>`);
   - **сповіщення** з outbox (Mini App сама надсилати не вміє) з кнопкою, що відкриває потрібний екран Mini App;
   - швидкі дії прямо в сповіщенні, де це одна кнопка без вводу (наприклад «Підтвердити оплату», «Показ відбувся»);
   - ~~чат об'єкта на беті — у боті~~ → змінено [ADR 0005](0005-chat-in-app.md): чат у застосунку, бот лише сповіщає;
   - запасний шлях для файлів: якщо в клієнті Telegram не працює вибір файлу в Mini App, файл (довідка ДРРП, `.p7s`, квитанція) можна надіслати боту.
3. **API (FastAPI) — основний вхід з M0/M1**, а не «пізніше». Бот і Mini App — обидва тонкі, викликають ті самі сервіси модулів (правило 2 CLAUDE.md без змін).
4. **Автентифікація Mini App — лише на бекенді.** Фронтенд надсилає `initData` у заголовку кожного запиту, бекенд перевіряє підпис HMAC (ключ із токена бота) і свіжість `auth_date` (поріг — у конфігурації). Telegram ID → `auth_identities`. У фронтенді немає жодних секретів.
5. **Фронтенд:** `web/` — React + TypeScript + Vite, менеджер пакетів `pnpm`. Типи API генеруються з OpenAPI-схеми FastAPI, щоб фронт і бек не розходились. Тексти — лише у файлах локалізації `web/src/locales/uk.json`. Тема — з параметрів Telegram (світла/темна), акценти — кольори бренду.
6. **Хостинг на беті:** GitHub Pages, `https://dramorr.github.io/domovyk/app/` (лендинг лишається в корені). CORS бекенду дозволяє лише origin Pages (у конфігурації). Перед платними функціями чи якщо Pages стане тісним — переїзд на власний домен (Cloudflare Pages або той самий сервер); у боті змінюється лише URL у BotFather і конфігурації.
7. **Номер телефону (FR-USR-1)** — через `requestContact` Mini App; запасний шлях — кнопка «Поділитися контактом» у боті.

## Розглянуті варіанти

| Варіант | Чому ні |
|---|---|
| Лише бот (SPEC v0.2) | Складні екрани в чаті незручні, а роботу по них довелося б зробити двічі |
| Mini App на власному сервері з першого дня | Зайві гроші й адміністрування до появи користувачів; Pages достатньо для статики |
| Окремий сайт замість Mini App | Втрачаємо вхід без реєстрації через Telegram і сповіщення в тому ж місці |

## Наслідки

- **Етапи:** M0 додатково включає каркас `web/`, деплой Mini App на Pages, скелет API з перевіркою `initData` і кнопку меню бота. Готово, коли: бот на `/start` відкриває Mini App, і вона показує ім'я користувача, отримане з бекенду. Кожен наступний етап постачає API + екрани Mini App + потрібні сповіщення бота. Порядок M1–M8 без змін.
- **`BOT_FLOWS.md`** стає описом екранів для обох каналів: кожен екран позначається, де він живе (Mini App / бот). Розділи переписуються по мірі етапів; до того вони — опис логіки екрана, а не обов'язково чат-реалізації.
- **FSM у боті** зменшується до чату й запасних сценаріїв.
- **Розробка локально:** Telegram відкриває Mini App лише за HTTPS. У dev — Vite dev server + тунель (наприклад `cloudflared`) або тестове середовище Telegram; локальний API теж через тунель.
- **Обмеження GitHub Pages:** умови Pages не дозволяють використовувати його як хостинг комерційного SaaS. Безкоштовна бета це не порушує, але перед платними функціями (FR-PAY-9) переїзд обов'язковий.
- **Публічність фронтенду:** весь код Mini App видно всім — це нормально, бо права перевіряє лише бекенд (FR: «підробку чужого ID ловить сервіс»).
