# 0013 — Кімнати поки не здаємо

- Статус: **прийнято**
- Дата: 2026-11-09
- Автор: Олег
- Зачіпає: SPEC FR-PRP-3, FR-SRC-2; BOT_FLOWS PRP-UNITS, LSE-NEW; API `/properties/{id}/rooms`

## Контекст

Схема з першого дня підтримує юніти: «весь об'єкт» і окремі кімнати (`units.kind = entire | room`), а сервіс не дає одночасно здавати весь об'єкт і кімнату в ньому. Покімнатна оренда — інша взаємодія: короткі домовленості, часто без письмового договору, сусіди-орендарі, спільна комуналка. Головна цінність Домовика (договір через Дію, облік оплат, комуналка на одного відповідального орендаря) там потрібна менше, а інтерфейс ускладнює для всіх: вибір «що здаєш», розділ «Кімнати» в картці.

## Рішення

У бета-версії здається лише об'єкт цілком.

- Ендпоїнти `POST/DELETE /api/v1/properties/{id}/rooms` прибрано, у Mini App немає розділу «Кімнати» й вибору юніта в новій оренді.
- Модель даних (`units`, `kind = room`), сервісні `add_room` / `remove_room` і правило «не можна одночасно весь об'єкт і кімнату» лишаються разом із тестами — повернути кімнати можна, додавши ендпоїнти й інтерфейс усередині картки об'єкта.
- `unit_id` у створенні оренди лишається необов'язковим (None = весь об'єкт).

## Наслідки

- Простіший шлях власника: об'єкт → оренда, без проміжного вибору.
- Фільтр пошуку «кімната» (FR-SRC-2) у бета-версії не робимо.
- Якщо попит на покімнатну оренду з'явиться — окреме рішення: як ділити комуналку й хто відповідальний орендар.
